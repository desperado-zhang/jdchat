# 历史咨询采集联调记录

记录日期：2026-08-19

## 1. 验证范围

本次只验证客服手动进入“历史咨询”并手动打开一条历史会话后的被动采集链路。

边界：

```text
不自动点击发送
不写入输入框
不自动遍历历史会话
不主动请求京东接口
不输出客户名、消息正文、pin、订单等敏感内容
```

## 2. 环境状态

```text
后端版本：0.1.1
插件版本：0.1.2
本机服务：http://127.0.0.1:8765
数据库：data/jdchat.sqlite3
```

咚咚页面注入状态：

```text
networkHooksEnabled=false
WebSocket wrapped=false
fetch wrapped=false
XHR wrapped=false
```

## 3. 操作路径

```text
1. 客服进入 https://dongdong.jd.com/
2. 点击左侧顶部“历史咨询”时钟 tab
3. 手动点开当前可见的一条历史会话
4. 等待插件 session/dom 被动事件上报
5. 使用 /capture/events/recent 查看元数据
```

历史入口结构：

```text
.c_tabs-tab[title="历史咨询"]
.list-compatible.recent-user-w
.alluser-item
```

## 5. 结论

手动打开历史咨询会话后，插件可以被动采集已渲染出的历史消息，并且事件带有 `pageContext` 元数据。后端 `/capture/events/recent` 能确认该事件来自历史咨询场景。

当前方案仍保持低风险边界：插件不主动调用接口、不自动切换客户、不自动遍历历史会话。

## 6. 后续建议

```text
1. 增加本机只读验证脚本，周期输出 recent event 元数据。
2. 增加插件状态 UI，展示队列长度、最近上报时间、当前 sidebar tab。
3. 历史补全只支持人工打开单会话后的低频滚动补全，不做批量自动切换。
```
